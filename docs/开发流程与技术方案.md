# Janus 开发流程与技术方案

> 文档版本：v0.2  
> 日期：2026-11-20  
> 阶段：M1 应用壳已完成 / M2 本地学习闭环已完成 / M3 听力与媒体模块已完成  
> 目标平台：Windows 10/11 桌面端  
> 实现基线：Tauri 2.12.6 + React 19.3.1 + TypeScript 7.0.2 + Vite 8.3.8  
> 当前范围：记录 M1/M2/M3 实际实现与验收结果，并维护 M4 之后的开发、架构、测试和风险方案

## 1. 产品目标与边界

Janus 是太阳系软件系列中的语言学习软件，初期聚焦英语，架构上支持后续扩展其他外语。

项目已完成品牌、UI、架构与方案冻结，并完成 M1 桌面应用壳。当前进入“从可视化底座到最小本地学习闭环”的过渡阶段，后续所有开发仍以本文件定义的架构边界为准。

### 1.1 当前实施状态

已完成的 M1 范围：

- Tauri 2 Windows 桌面工程可启动、可构建；
- 无边框窗口、自定义标题栏、最小/最大/关闭与最大化状态同步；
- 原生拖拽与双击标题栏最大化/还原；
- 浅色/深色主题切换与本地持久化；
- 今日学习、单词、句子、听力、朗读、AI 对话、生词本、学习数据与设置入口；
- `Ctrl+1` 至 `Ctrl+6` 导航、`Ctrl+K` 搜索与快速跳转；
- 1360×820 常规布局、1040×700 最小窗口、纵向滚动与紧凑侧栏；
- Tauri capability 最小授权、原生拖拽 ACL、玻璃效果降级与 close-hover 语义 Token；
- TypeScript、Vitest、Vite 与 Rust 检查链路。

M1 明确不包含：

- SQLite 与真实学习数据；
- 课程内容、练习状态与反馈算法；
- AI 服务、麦克风、ASR、TTS 与发音评分；
- 安装包签名、自动更新与正式发布。

### 1.2 设计与技术立项验收边界

- 单词、句子、听力、朗读、AI 对话的功能与技术方案；
- 多语言扩展机制；
- 学习数据、反馈、风险与迭代计划；
- Windows WebView2 桌面启动、窗口交互与响应式布局验证。

仍待后续里程碑验证：

- 真实设备上的麦克风、音频播放、设备切换与回声；
- ASR、TTS、LLM 与发音评分的供应商组合；
- 大规模训练内容与内容运营后台；
- 多端同步、社区功能与正式商店发布；
- 英语之外其他语言的完整语音与评分能力。

### 1.3 用户与场景

核心用户：

- 具备基础英语能力、希望提升真实听说能力的学习者；
- 需要短时高频练习的桌面用户；
- 希望获得即时反馈，但不愿被游戏化和广告打断的用户。

典型场景：

1. 每天早上 15–30 分钟复习单词与句子；
2. 用一段 1–3 分钟材料做精听与跟读；
3. 在固定情景中与 AI 进行 3–8 轮语音对话；
4. 在通勤前或睡前查看学习数据与下一次复习内容。

- 发音与表达反馈；
- 本地学习记录与统计；
- 浅色/深色主题、键盘操作、可信的失败降级。

### 2.2 P1：增强版本

- 学习计划与提醒；
- 生词本与错题本；
- 多场景角色对话；

## 3. 技术选型

| 层次 | 选择 | 当前状态 | 理由 |
| --- | --- | --- | --- |
| 桌面壳 | Tauri 2.12.6 | 已接入 | 小体积、Rust 后端、Windows WebView2、权限模型清晰 |
| 前端 | React 19.3.1 + TypeScript 7.0.2 + Vite 8.3.8 | 已接入 | 与系列项目一致，组件化、类型安全与快速构建 |
| 样式 | 原生 CSS + `design/tokens.css` | 已接入 | 避免重主题框架，浅/深主题和响应式规则共用语义 Token |
| IPC | Tauri Commands + capability ACL | M2 已接入 | 窗口控制命令与学习闭环命令（typed IPC + 统一错误模型）均已跑通 |
| UI 状态 | React 本地状态 / 按需引入轻量 store | M2 已接入 | 壳层状态 + 复习/句子/生词本/统计异步数据 |
| 数据 | SQLite（`rusqlite` 0.31 bundled） | M2 已接入 | 本地优先、事务可靠、WAL、离线可用、易迁移 |
| 数据访问 | Rust `rusqlite` | M2 已接入 | 参数化查询、迁移、事务与类型校验 |
| 音频 | Web Audio API + AudioWorklet | 计划于 M3/M4 | 录制、播放、波形、速度与打断控制 |
| AI 网关 | Rust 服务层 + Provider Adapter | 计划于 M4/M5 | 隐藏密钥、统一超时/重试/降级与配额 |
| 流式传输 | WebSocket / WebRTC（按供应商） | 计划于 M5 | 低延迟语音输入输出 |
| 测试 | Vitest 5.1.1 + Rust tests；后续接入 Playwright | 部分接入 | 已覆盖主题逻辑与 Rust/前端编译；桌面关键路径后续自动化 |
| 打包 | Tauri Bundle / MSI 或 NSIS | 工程已配置 | Windows 安装、签名与更新策略在发布阶段完成 |

### 3.1 关键原则

- 本地优先：没有网络时，单词、句子、听力、复习与本地录音仍可用。
- 最小权限：仅请求麦克风、文件系统与网络所需权限。
- 秘密不进前端：AI 密钥保存在 Rust 侧或系统凭据存储。
- 可替换：ASR、TTS、LLM、发音评分均为 Adapter，不把供应商类型泄漏到业务层。
- 可取消：流式请求、音频播放与录音必须支持明确的取消与资源回收。
- 可迁移：数据库 schema、Prompt、模型配置和 Language Pack 都有版本号。

## 4. 系统架构

```text
┌────────────────────────────────────────────────────┐
│                  Tauri Shell / Window               │
│  标题栏 · 窗口控制 · 权限 · 更新 · 托盘（可选）      │
└───────────────────────┬────────────────────────────┘
                        │ typed IPC
┌───────────────────────▼────────────────────────────┐
│                 React Learning UI                  │
│ 工作台 · 单词 · 句子 · 听力 · 朗读 · 对话 · 统计    │
└──────────────┬───────────────────┬─────────────────┘
               │                   │
     ┌─────────▼─────────┐   ┌─────▼───────────────┐
     │  Learning Engine  │   │   Audio / Voice    │
     │ SRS · Session     │   │ VAD · playback     │
     │ Feedback · Plan   │   │ capture · captions │
     └─────────┬─────────┘   └─────┬───────────────┘
               │                   │
     ┌─────────▼───────────────────▼───────────────┐
     │             Rust Application Core            │
     │  IPC validation · AI Gateway · repositories  │
     │  migrations · credentials · cache · logs     │
     └──────────────┬──────────────┬────────────────┘
                    │              │
          ┌─────────▼──────┐  ┌────▼────────────────┐
          │ SQLite + Files │  │ Cloud AI Providers  │
          │ local-first    │  │ ASR LLM TTS scoring │
          └────────────────┘  └─────────────────────┘
```

### 4.1 信任边界

- WebView 渲染层视为不可信，所有 IPC 输入必须序列化、校验与限长。
- 文件路径、网络地址、模型参数不得由任意页面文本直接控制。
- Rust 侧持有凭据与网络访问策略，前端只接收经过脱敏的会话事件。
- 音频、转写与学习记录默认留在本地；上传前显示用途与开关。

### 4.2 关键数据流

1. 用户打开应用 → Rust 初始化数据库与迁移 → React 读取本地学习状态。
2. 单词复习 → Learning Engine 计算下一次复习时间 → 事务写入 attempt/review state。
3. 听力播放 → 本地媒体索引定位句子 → AudioWorklet 输出 → UI 更新播放状态。
4. 朗读 → 麦克风采集 → VAD 分段 → 上传或本地 ASR → 评分 → 内联反馈。
5. AI 对话 → VAD → 流式 ASR → LLM → 流式 TTS → 可打断播放 → 会话结束生成总结。
## 5. 模块划分

| 模块 | 责任 | 关键输出 |
| --- | --- | --- |
| App Shell | 窗口、标题栏、主题、快捷键、权限 | 可启动的 Windows 壳 |
| Workspace | 今日路径、目标、复习队列 | 工作台与学习入口 |
| Word Lab | 词卡、释义、例句、发音、生词本 | 单词学习闭环 |
| Sentence Lab | 句子、语块、翻译、拆解、跟读 | 句子理解与产出 |
| Listening Lab | 音频、字幕、逐句、听写、速度 | 精听与泛听 |
| Speaking Lab | 录音、ASR、评分、对比、纠错 | 朗读与发音反馈 |
| Conversation | 场景、实时语音、打断、总结 | AI 对话闭环 |
| Review Engine | SRS、到期队列、掌握度 | 可靠复习调度 |

| AI Gateway | ASR/LLM/TTS/评分、超时、重试、降级 | 统一 AI 接口 |

### 5.1 建议目录

```text
Janus/
  assets/brand/          # Logo、字标、Windows 图标与品牌板
  design/                # 设计规范、Token 与高保真预览
  docs/                  # 开发与功能技术方案
  src/
    components/          # 标题栏、侧栏、搜索、Toast 等通用组件
    data/                # M1 导航与静态模块元数据
    lib/                 # 主题、桌面窗口 API 与单元测试
    pages/               # 工作台与模块底座页面
    styles/              # 基础、布局、页面与浮层样式
    test/                # Vitest setup
    App.tsx              # 应用壳、导航、快捷键与状态
    main.tsx             # React 入口
  src-tauri/
    capabilities/        # Tauri 窗口与拖拽 ACL
    src/                 # Rust 窗口命令与应用入口
  dist/                  # Vite 生产构建
```
M2 起逐步增加 `domain/`、`features/`、`services/`、`language-packs/` 与 Rust 侧 `db/`、`commands/`、`security/`；目录只在有真实实现时创建，避免空架构。

前端 `domain/` 不依赖 Tauri API；Rust 侧也不依赖 UI 组件。IPC 层负责二者之间的 DTO 与错误映射。

### M3：听力与媒体（已完成）

实际实现（2026-11-20）：

- 20 条真实英文语音（Windows 离线 TTS，16kHz/16bit/mono）内嵌于安装包，首次启动写入 `media_cache`；
- SQLite 迁移 v2：`listening_clips`、`listening_segments`、`dictation_attempts` 三表 + `deleted_seed_clips` 墓碑表；
- 播放器：播放/暂停、进度定位、0.75× / 1.0× / 1.25× 变速、单句循环、字幕开关、双语字幕条；
- 句段定位：按句记录 `start_ms` / `end_ms`，句段可点击跳转；
- 听写判断：后端规范化文本并判分（`normalize_dictation_text`），记录时长/正误/原文回显，前端不自行评分；
- 听写统计：累计、今日、正确率与薄弱片段 Top5；
- 删除策略：级联删除听写记录与媒体文件，写墓碑防止重启后复活；
- 媒体访问：Tauri `assetProtocol`（`$APPDATA/**`、`$RESOURCE/**`）+ `protocol-asset` feature，不暴露绝对路径给前端；
- 回归：Rust 12 项 + 前端 8 项测试全绿。

出口条件（已满足）：至少 20 条真实片段可稳定播放与定位。

## 7. 开发流程

每个功能按以下顺序推进：

1. 需求与界面状态清单；
2. 数据模型与失败路径设计；
3. 先做可运行原型；
4. 单元与集成测试；
5. E2E 与真实窗口验收；
6. 性能与无障碍回归；
7. 文档与变更记录。

禁止事项：

- 先写大量页面再补数据模型；
- AI 功能没有超时、取消与降级；
- 业务组件直接调用供应商 API；
- 把密钥写进前端环境变量；
- 用无法解释的总分替代反馈；
- 无测试地修改 SRS 与复习状态。

## 9. 风险计划

| 风险 | 概率 | 影响 | 缓解策略 | 触发信号 |
| --- | --- | --- | --- | --- |
| AI 首包延迟过高 | 高 | 高 | 分段流式、预连接、短回复、TTS 先行、文字降级 | 首段响应 p95 > 2 s |
| AI 成本不可控 | 中 | 高 | 会话时长上限、缓存、模型分级、用量预算 | 单会话成本超过预算 |
| ASR 对非母语口音误差大 | 高 | 高 | 提示重读、置信度阈值、可编辑转写、多供应商 | 关键短句重复识别失败 |
| 发音评分不可解释 | 高 | 高 | 展示维度与证据、低置信度不强判、人工可回放 | 用户无法理解扣分原因 |
| 音频设备与回声问题 | 中 | 高 | 设备检测、回声消除、耳机建议、扬声器回退 | 频繁自听或录音空白 |
| 供应商断网或模型升级 | 中 | 高 | Provider Adapter、固定模型版本、回归集、降级模式 | 错误率突增或输出风格变化 |
| 内容版权与授权 | 中 | 高 | 自有/授权材料、来源字段、下架流程 | 内容来源不完整 |
| 隐私与录音泄露 | 低 | 极高 | 本地优先、默认不持久化、最小上传、加密与清除 | 日志出现音频或个人信息 |
| 多语言复杂度被低估 | 高 | 中 | Language Pack 接口先行、只做英语完整版 | 业务层出现英语专用判断 |
| SRS 变更破坏历史 | 中 | 高 | 版本化调度器、迁移、回滚与对照测试 | 用户复习间隔异常跳变 |
| Windows 多版本兼容 | 中 | 中 | 真实设备矩阵、WebView2 检查、安装器测试 | 启动失败或音频无权限 |
| UI 信息过密 | 中 | 中 | 设计 Token、内容优先级、窄窗口验收 | 1040×700 出现遮挡 |

## 10. 发布与更新

- 使用 Tauri Bundle 生成 Windows 安装包；
- 发布前完成代码签名与安装器签名；
- 更新包必须校验签名，并支持失败回滚；
- 数据库迁移只向前升级，重大变更提供备份；
- 更新说明区分“内容更新”“模型配置更新”“应用更新”；
- AI 供应商或 Prompt 变更需要独立版本号与回归记录；
- 崩溃日志与诊断默认关闭，用户明确开启后才上传；
- 卸载时默认保留用户学习记录，并提供彻底删除选项。

## 11. 隐私与安全基线

1. 录音默认只存在于内存与临时文件，练习结束即清理。
2. 上传 AI 服务前告知目的；用户可选择仅文字模式。
3. Prompt、日志与崩溃报告不得包含完整录音、密钥或无关个人数据。
4. 网络请求使用 TLS，证书校验不可关闭。
5. 本地数据库敏感字段与备份策略在实现前完成威胁建模。
6. Tauri capability 按窗口与命令最小授权。
7. 第三方内容与模型许可在发布清单中登记。
