# Janus 功能与技术方案

> 文档版本：v0.2  
> 日期：2026-11-20  
> 当前目标语言：英语  
> 长期目标：通过 Language Pack 支持其他外语  
> 实现状态：M1 桌面应用壳已完成 / M2 本地学习闭环已完成 / M3 听力与媒体模块已完成；朗读、AI 语音与云端服务仍为待实现方案  
> 文档范围：功能、交互、数据结构、AI 语音、多语言与迭代验收标准

### 当前实施状态

- 已实现：Windows 桌面壳、主题、导航、搜索、模块入口与响应式布局（M1）；
- 已实现：SQLite 本地数据层、20 个种子单词 + 20 个种子句子、SRS 复习、生词本、学习数据、导出与清除（M2）；
- 已实现：20 条真实英文语音、听力播放器（变速/逐句循环/字幕）、后端听写判分与统计、片段删除与墓碑（M3）；
- 尚未实现：朗读录音、ASR、TTS、发音评分、AI 实时语音对话与云端服务；
- 因此本文中涉及朗读、AI 语音与多语言扩展的模块接口、事件模型、延迟预算与验收条件仍是 M4–M6 的实现契约；
- 已落地的本地闭环全部由真实数据与真实操作驱动，不伪造评分或模拟 AI。

## 1. 产品能力与成功标准

Janus 的核心不是“提供很多课程”，而是让学习者在同一个工作台完成：

**接触语言 → 理解结构 → 主动回忆 → 开口表达 → 得到反馈 → 进入长期复习。**

首个可用版本应验证四条闭环：

1. 单词复习能稳定记录并合理安排下一次复习；
2. 句子学习能帮助用户理解语块与结构，而不只是翻译；
3. 听力与朗读能形成输入和输出的连续练习；
4. AI 对话能在低延迟下完成多轮交流，并给出可理解的纠错。

成功指标建议：

- 首次使用 5 分钟内可完成第一个学习动作；
- 第 7 天仍能完成一次有效复习的用户比例；
- 单词复习到期完成率；
- 听力跟读完成率与重听次数；
- AI 对话轮次、打断成功率与首段响应延迟；
- 用户能解释“为什么推荐这次复习/这条纠错”的比例；
- 不依赖连续打卡强迫，而以学习行为稳定性衡量留存。

## 2. 学习模型

Janus 采用五阶段学习循环：

| 阶段 | 目标 | 产品映射 |
| --- | --- | --- |
| 输入 | 接触真实语言 | 听力材料、例句、AI 对话 |
| 注意 | 看见结构与差异 | 语块拆解、错音标注、内联纠错 |
| 练习 | 主动产出 | 填空、造句、跟读、角色对话 |
| 反馈 | 理解问题与下一步 | 维度评分、证据、重试建议 |
| 巩固 | 进入长期记忆 | SRS 复习、错题/生词本、周复盘 |

### 2.1 掌握度不是单一分数

每个学习项保留多类状态：

- 识别过；
- 能回忆；
- 能在句子中使用；
- 能听懂；
- 能自然说出；
- 最近一次复习的置信度。

最终“掌握”由多类证据组合，不把一次正确或一个 AI 总分当作掌握。

## 3. 多语言扩展机制

### 3.1 两层语言设置

- **UI Locale**：界面语言，如中文、英文；
- **Target Language**：正在学习的语言，如英语、日语。

两者独立保存。中文界面可以学习英语，英文界面也可以学习其他语言。

### 3.2 Language Pack 接口

每个语言包至少提供：

```ts
interface LanguagePack {
  id: string;                 // en, ja, ko, fr ...
  displayName: string;
  uiLocale: string;
  script: ScriptProfile;       // 字符集、大小写、书写方向
  phonology: PhonologyProfile;
  tokenizer: TokenizerProfile;
  morphology: MorphologyProfile;
  segmentation: SegmentationProfile;
  speech: SpeechProfile;       // ASR/TTS voice ids, sample rates
  assessment: AssessmentProfile;
  prompts: PromptProfile;      // 对话、纠错、解释模板
  contentSchemaVersion: number;
}
```

### 3.3 语言相关能力

| 能力 | 英语需求 | 扩展时需要抽象的点 |
| --- | --- | --- |
| 分词 | 空格分词 + 缩写 | 无空格语言、词素、字符边界 |
| 音系 | 音素、重音、连读 | 声调、音高重音、音节结构 |
| 书写 | LTR、大小写 | RTL、竖排、字符组合 |
| 发音评分 | 音素 + 韵律 | 声调、节奏、语速、清晰度 |
| TTS | 连读、语气 | 发音人、语速、情感、方言 |
| ASR | 流式英文 | 语言码、混合语言、口音 |
| 语法 | 词性、时态、句法 | 格、敬语、助词、语序 |

### 3.4 反模式

- 在业务代码中写 `if language === 'en'`；
- 把字符数作为句子长度统一指标；
- 用英文空格分词处理所有语言；
- 把英语音素评分维度的名称直接复用到所有语言；
- 把 TTS 与 ASR 供应商的原始字段直接进入 UI。

## 4. 单词学习模块

### 4.1 学习目标

用户不只是“认识释义”，而是逐步做到：

- 听音识别；
- 看见拼写回忆含义；
- 在语境中理解词义；
- 主动造句；
- 正确发音；
- 在间隔复习中稳定保留。

### 4.2 词卡结构

前台：

- 单词与词性；
- 音标与发音按钮；
- 一个核心释义；
- 一个真实例句；
- “显示答案”或主动回忆入口。

翻面：

- 多个义项与语域；
- 搭配、词族、近反义；
- 例句与翻译；
- 发音与跟读；
- 记忆提示或来源说明；
- “认识 / 模糊 / 不认识 / 太简单”四档反馈。

### 4.3 复习调度

初版使用独立 `ReviewScheduler` 接口，内部可采用 FSRS 类算法或经过验证的 SRS 算法。

输入：

- 用户评级；
- 响应时间；
- 是否提示；
- 历史稳定性与难度；
- 当前学习阶段。

输出：

- 下一次到期时间；
- 稳定性、难度与可提取性估计；
- 推荐卡型；
- 调度器版本号。

安全要求：

- 调度算法版本与数据一起保存；
- 算法升级必须能做对照与回滚；
- 不因一次误点把复习间隔大幅推远；
- “太简单”不应永久移除单词，而是降低出现频率；
- 所有到期时间按本地时区计算，并保存绝对时间。

### 4.4 生词本与错题本

- 用户主动收藏；
- 复习中多次失败自动进入“需要关注”；
- 可按考试、主题、来源、词性筛选；
- 可一键生成 5–10 分钟专项练习；
- 错误记录保存“错因类型”，而不是只保存错误答案。

## 5. 句子学习模块

### 5.1 目标

从“逐词翻译”升级为“按语块理解并主动产出”。

### 5.2 内容结构

- 原句与标准音频；
- 用户可读翻译；
- 语块切分；
- 关键词与搭配；
- 语法标签；
- 语气与使用场景；
- 可选音标或连读提示。

### 5.3 学习动作

1. 先听后读；
2. 按语块拆解；
3. 隐藏翻译并回忆含义；
4. 完成关键词填空；
5. 用目标结构造句；
6. 跟读并比较节奏；
7. 加入复习队列。

### 5.4 语块标注

示例：

`It depends on / how you look at it.`

语块数据包含：

- 起止字符或 token；
- 语块类型；
- 是否固定搭配；
- 可选中文解释；
- 可选音频时间范围。

不把所有句子切得过碎。一般每句 2–5 个语块，优先保留可迁移的表达单元。

## 6. 听力模块

### 6.1 训练模式

| 模式 | 目的 | 交互 |
| --- | --- | --- |
| 泛听 | 熟悉语音流与主题 | 连续播放、速度调整 |
| 精听 | 识别细节与结构 | 逐句循环、隐藏字幕 |
| 听写 | 主动重建文本 | 输入/校验、错误定位 |
| 影子跟读 | 模仿节奏与连读 | 跟读录音、波形对比 |
| 情境听辨 | 抓取意图与语气 | 选择题、复述、AI 追问 |

### 6.2 播放器

> M3 已实现：播放/暂停、进度定位、0.75× / 1.0× / 1.25× 变速、单句循环、双语字幕条与句段点击定位。前后 5 秒跳转、A-B 循环、音量/输出设备切换与录音对比留待后续里程碑。

- 播放/暂停、前后 5 秒；
- 0.75× / 1.0× / 1.25×；
- 逐句定位；
- A-B 循环；
- 字幕显示：原文 / 隐藏 / 双语；
- 音量与输出设备切换；
- 录音回放与 A/B 对比。

### 6.3 媒体数据处理

> M3 已实现：音频与字幕（文本）分开存储；句子区间保存 `start_ms` / `end_ms` 与稳定 id；音频使用本地缓存（`media_cache`）且允许删除（写墓碑防复活）；前端通过 Tauri asset 协议访问媒体，不暴露绝对文件路径。

- 音频与字幕分开存储；
- 句子区间保存 `start_ms`、`end_ms` 与稳定 id；
- 断句与字幕版本有记录；
- 音频使用本地缓存，允许删除；
- 不把绝对文件路径暴露给前端组件。

## 7. 朗读与口语模块

### 7.1 练习流程

1. 选择句子或短段；
2. 听原音；
3. 显示文本与音素提示；
4. 录音；
5. 回放并比较；
6. 获得转写与多维反馈；
7. 重点音素二次跟读；
8. 将问题词/句加入复习。

### 7.2 评分维度

| 维度 | 说明 | 呈现 |
| --- | --- | --- |
| 完整度 | 是否读出目标内容 | 漏读/多读提示 |
| 准确度 | 音素与单词是否正确 | IPA 与词级标记 |
| 流利度 | 停顿、语速、重复 | 时间轴与重读段落 |
| 韵律 | 重音、语调、节奏 | 轻量提示，不假装绝对客观 |
| 转写置信度 | ASR 是否确定 | 低置信度建议重录 |

### 7.3 反馈原则

- 先给一个可执行的改进点，再展示分数；
- 评分必须可以回听与对照；
- 分清“模型不确定”和“用户确实错误”；
- 方言与口音差异不应被当作错误；
- 对同一句提供重试，不只显示一次红叉；
- 不把 AI 评分作为正式语言能力认证。
## 8. AI 实时语音对话

### 8.1 目标

AI 对话不是“会说话的聊天框”，而是有场景、有目标、有反馈的语言练习空间。

首版支持：

- 实时语音输入；
- 流式识别；
- 流式语言生成；
- 流式语音合成；
- 用户可打断；
- 会话内轻量纠错；
- 会话后总结；
- 断网或无麦克风时降级为文字对话。

### 8.2 场景结构

每个场景包含：

- 场景标题与目标，如“在咖啡馆点单”；
- AI 角色与语气；
- 用户目标与限制；
- 目标词汇/句型；
- 推荐难度与 CEFR 范围；
- 结束条件；
- 会话后复习重点。

### 8.3 实时链路

```text
麦克风
  → AudioWorklet 采集
  → VAD / 端点检测
  → 流式 ASR（部分转写）
  → 对话编排器（上下文 + 场景策略）
  → 流式 LLM 文本
  → 流式 TTS
  → 播放与字幕
  → 用户可随时打断
```

### 8.4 状态与并发

会话编排器必须是一个显式状态机：

- Idle；
- Permission；
- Listening；
- Recognizing；
- Thinking；
- Speaking；
- Paused；
- Degraded；
- Ended；
- Error。

规则：

- 任何时刻只有一个主音频输出；
- 用户开始说话时立即停止 TTS；
- ASR、LLM、TTS 所有流都有取消令牌；
- 新的一轮对话不能复用上一轮未完成的请求上下文；
- 会话结束后再生成总结，不在每句话后强行说教。

### 8.5 延迟预算

| 阶段 | 目标 |
| --- | --- |
| 用户停止说话到端点检测 | 300–700 ms |
| 部分转写首字 | < 300 ms |
| 最终转写完成 | < 1 s |
| LLM 首 token | < 800 ms |
| TTS 首段音频 | < 500 ms |
| 首段可听回应 | 交互内 p95 < 2 s |

首版优先保证“能顺畅对话”，而不是追求极短的固定话术。超过 1.5 秒时必须显示当前阶段与可取消操作。

### 8.6 对话策略

- 角色保持情景，不自称“AI 老师”打断沉浸；
- 回复长度按难度限制，避免一次输出大段讲座；
- 遇到用户卡住时给一个提示或换一种问法；
- 优先纠正影响理解的错误；
- 不影响交流的小错误可在会话后汇总；
- 不伪造自己听到了用户未说的内容；
- 不把用户的口音转录错误当作语法错误。

### 8.7 纠错分类

| 类型 | 示例 | 呈现时机 |
| --- | --- | --- |
| 阻断理解 | 关键词错误、意图不明 | 会话中即时澄清 |
| 表达不自然 | 语法可懂但不地道 | 会话内轻量改写，会话后总结 |
| 发音问题 | 特定音素、重音、连读 | 朗读复练中反馈 |
| 流利度 | 停顿过多、重复 | 会话后时间轴总结 |
| 词汇升级 | 用更准确的搭配 | 会话后 1–3 个建议 |

### 8.8 会话总结

会话结束生成：

- 完成的目标；
- 1–3 个有效表达；
- 1–3 个最值得练习的问题；
- 可复用的替换表达；
- 自动加入复习的单词/句子；
- 用户是否愿意再次练习。

总结必须引用实际会话内容，不生成不存在的原句。

## 9. AI Gateway 设计

### 9.1 统一接口

```ts
interface AiGateway {
  transcribe(input: AudioChunkStream, options: AsrOptions): AsyncIterable<TranscriptEvent>;
  respond(input: DialogueTurn, options: LlmOptions): AsyncIterable<TextEvent>;
  synthesize(input: TextStream, options: TtsOptions): AsyncIterable<AudioChunk>;
  assessPronunciation(input: AudioBlob, target: TargetText): Promise<AssessmentResult>;
}
```

### 9.2 Provider Adapter

每个供应商实现：

- 凭据与区域配置；
- 音频格式、采样率与通道转换；
- 流式事件标准化；
- 超时、重试、限流；
- 错误码 → 用户文案；
- 模型版本记录；
- 成本与用量估算；
- 健康检查。

### 9.3 失败降级

| 失败 | 降级 |
| --- | --- |
| TTS 不可用 | 显示完整文字 + 系统语音或静音对话 |
| ASR 不可用 | 允许键盘输入，保留对话练习 |
| LLM 超时 | 场景提示句 + 重试，不循环等待 |
| 网络中断 | 本地单词/句子/听力继续，AI 模式暂停 |
| 麦克风占用 | 显示设备诊断与文字模式 |
| 评分低置信度 | 建议重录，不判为错误 |

## 10. 学习数据模型

建议 SQLite 核心表：

| 表 | 内容 |
| --- | --- |
| `learner` | 本地用户与偏好 |
| `language_profile` | 目标语言、难度、语音设置 |
| `content_item` | 单词、句子、听力片段等统一内容入口 |
| `content_variant` | 语言包版本、翻译、音频、字幕 |
| `lesson` | 一次学习计划或内容集合 |
| `attempt` | 每次作答、录音、听写、对话轮次 |
| `review_state` | 单词/句子的 SRS 状态 |
| `utterance` | 用户语音转写、评分与低置信度标记 |
| `correction` | 错误类型、证据、建议与是否采纳 |
| `session` | 一次学习/对话会话 |
| `event_log` | 可重放的学习事件 |
| `ai_trace` | 脱敏后的模型与延迟元数据（可选） |

### 10.1 事件优先

学习统计不应由 UI 临时拼装。关键行为统一记录为事件：

- `word_reviewed`
- `sentence_completed`
- `listening_played`
- `dictation_submitted`
- `speech_recorded`
- `pronunciation_assessed`
- `conversation_turn_completed`
- `correction_viewed`
- `review_scheduled`

事件包含 `occurred_at`、内容 id、语言包版本、客户端版本与匿名会话 id。统计数据从事件投影，便于解释与重建。

### 10.2 数据保留

- 默认保留学习结果与复习状态；
- 原始录音默认不保留；
- AI 对话默认只保存文本总结与必要的纠错证据；
- 用户可导出、删除和关闭云同步；
- 删除账号或重置学习数据必须覆盖数据库、缓存与备份。

## 11. 反馈与学习体验设计

### 11.1 三层反馈

| 层级 | 时机 | 内容 |
| --- | --- | --- |
| 即时反馈 | 当前操作后 0.2–2 秒 | 对/错、漏音、可重试提示 |
| 局部反馈 | 完成一个练习后 | 句内纠错、替换表达、下一步建议 |
| 会话反馈 | 对话或学习结束时 | 目标完成度、重点问题、复习入口 |

### 11.2 反馈表达

- 先肯定“做到了什么”，再指出“改哪里”；
- 最多显示 1 个主问题和 2 个次问题；
- 给出可执行动作，如“再读一次 /θ/”；
- 用证据解释：原音、用户音、时间轴、目标文本；
- 失败不等于惩罚：不扣连续天数，不播放负面音效；
- 低置信度明确标注“模型不确定”。

### 11.3 统计与可视化

首页展示：

- 今日目标与剩余分钟；
- 本周学习节奏；
- 到期复习数量；
- 最近进入长期记忆的内容；
- 错误类型趋势。

统计页展示：

- 输入/输出时间；
- 单词复习正确率；
- 听力完成与重听率；
- 朗读维度趋势；
- AI 对话轮次与打断率；
- 语言包与难度分布。

每个数字都要可解释，并能进入对应明细。

## 12. 可行性分析

| 能力 | 技术难度 | 主要风险 | MVP 策略 |
| --- | --- | --- | --- |
| 单词与 SRS | 中 | 调度与数据迁移 | 本地闭环，先稳定 |
| 句子拆解 | 中 | 内容质量与分词 | 人工可控结构 + 规则 |
| 听力播放 | 中 | 媒体同步与设备 | 本地优先、字幕索引 |
| 朗读 ASR | 高 | 口音、延迟、设备 | 分段识别 + 低置信度提示 |
| 发音评分 | 很高 | 可信度与解释性 | 维度化展示，不承诺认证 |
| AI 实时语音 | 很高 | 延迟、打断、成本 | 流式状态机 + 文字降级 |
| 多语言扩展 | 高 | 字符、音系、语序差异 | Language Pack 接口先行 |
| 本地数据与隐私 | 中 | 录音、日志、备份 | 默认不持久化音频 |

### 12.1 最大技术不确定性

1. 真实 Windows 设备上的麦克风、回声与设备切换；
2. 供应商流式 ASR/TTS 的首包延迟与打断行为；
3. 非母语口音的评分可信度；
4. 模型升级导致的对话与纠错漂移；
5. 多语言对分词、音系与评分接口的压力。

M4 开始前必须先用真实 Windows 设备完成麦克风、播放、设备切换与回声 spike；M5 的具体供应商组合在完成延迟、成本与打断验证后再冻结。

## 14. 验收标准

### 单词

- 可完成至少 20 张词卡的一轮复习；
- 到期时间可解释且重启后保持；
- 评分反馈不会因为一次误点导致不可逆跳变。

### 句子

- 至少 20 个句子支持语块、翻译与音频；
- 用户可隐藏翻译后主动回忆；
- 句子完成事件可进入复习和统计。

### 听力

- 播放、暂停、逐句循环与速度调整稳定；
- 字幕与音频区间可对齐；
- 断网时已缓存内容可继续学习。

### 朗读

- 麦克风权限、录音、回放与删除完整；
- 低置信度 ASR 不直接判错；
- 反馈带至少一条可执行改进建议。

### AI 对话

- 至少一个场景完成 3–8 轮可打断对话；
- 首段响应 p95 达到目标或可明确降级；
- 断网、无麦克风、ASR 失败均有可继续的路径；
- 会话总结引用真实对话内容。

### 多语言架构

- 业务层不出现硬编码英语判断；
- 新语言包可加载独立分词、音系、Prompt 与语音配置；
- UI 不因更长文本或 RTL 方向出现阻断性裁切。

## 15. 待决策问题

1. 首个 AI 语音供应商组合采用一体化 Realtime API，还是拆分 ASR/LLM/TTS？
2. 发音评分使用供应商专有能力，还是自建音素对齐与规则评分？
3. 内容版权模型：自有内容、授权内容还是用户导入？
4. 是否在 v0.1 就提供云同步，还是坚持纯本地？
5. 复习算法使用 FSRS 类实现还是经过验证的更简单调度器？
6. 其他语言的首个验证目标：日语、西班牙语或其他？

这些问题不阻塞 M1 桌面壳验收；涉及数据模型与算法的问题应在 M2 开工前形成 ADR，涉及供应商与实时语音的问题应在 M4/M5 决策门前形成 ADR。
